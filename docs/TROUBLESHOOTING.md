# 故障排查

先遵循一个原则：遇到不确定情况，退出 Codex 实时语音、停止门控，并把 Codex 麦克风恢复为“系统默认”。

当前版本只验证没有其他 Codex 任务同时运行的单任务场景。多任务并行时请先停止测试，等待其他任务结束后再启动门控和实时语音。

## 双击启动脚本没有反应

从 PowerShell 手动运行，以保留错误信息：

```powershell
Set-Location <项目目录>
.\启动Codex实时语音小欧门控.cmd
```

检查：

- `.venv\Scripts\python.exe` 是否存在。
- 模型目录名称是否完全匹配。
- 脚本是否被 Windows 安全策略或杀毒软件阻止。

## 提示找不到模型

模型应位于：

```text
models/sherpa-onnx-kws-zipformer-zh-en-3M-2025-12-20/
```

常见错误是多解压了一层，形成：

```text
models/sherpa.../sherpa.../encoder....onnx
```

把内层模型目录移动到正确层级即可。不要把模型提交到 Git。

## 预检找不到 VB-CABLE

```powershell
.\.venv\Scripts\python.exe .\preflight_virtual_audio.py
```

若提示缺失：

1. 确认驱动来自 VB-Audio 官网。
2. 确认安装后已经真正重启 Windows。
3. 打开 Windows“系统 > 声音”，检查输入设备中是否有 `CABLE Output`、输出设备中是否有 `CABLE Input`。
4. 不要把设备编号写死到代码或脚本中。

## Codex 完全听不到声音

按顺序检查：

1. 门控窗口是否仍在运行。
2. Codex 麦克风是否选中 `CABLE Output`，不是 `CABLE Input`。
3. 是否还有其他 Codex 任务正在运行；若有，先等待它们结束并重新启动实时语音。
4. 是否已经说“小欧”，终端是否显示“已唤醒，正在放行”。
5. Windows 麦克风权限是否允许桌面应用访问。
6. 是否有其他程序独占真实麦克风。

如果预检失败，不要强行把路由改到默认扬声器。

## 说“小欧”没有唤醒

- 保持正常语速，单独清晰说“小欧”。
- 离麦克风更近，减少背景噪声。
- 确认真实麦克风是 Windows 默认输入。
- 先运行 `启动小欧门控原型.cmd`，隔离 Codex 和 VB-CABLE 的影响。
- 使用 `验收小欧门控原型.cmd` 检查十组场景。

不要通过大幅降低阈值来掩盖问题；这会增加误唤醒。

## 说“结束”后 Codex 仍然回答

1. 查看终端是否出现“已结束，恢复静音”。
2. 等待已经发送给 Codex 的上一段音频处理完毕。
3. 再说一句普通测试语；不要包含“小欧”。
4. 如果仍能触发新响应，立即退出实时语音并停止程序。

门控只能阻止后续音频，无法撤回已经进入 Codex 的音频。

## 安装 VB-CABLE 后系统没有声音

驱动安装可能改变 Windows 默认设备：

1. 打开“系统 > 声音”。
2. 在“输出”中重新选择原来的扬声器或耳机。
3. 在“输入”中重新选择原来的真实麦克风。
4. 重新启动受影响的应用。

不要把 `CABLE Input` 或 `CABLE Output` 永久设为系统默认设备。

## 终端出现乱码或编码错误

启动脚本会启用 UTF-8。手动运行时可先执行：

```powershell
$env:PYTHONUTF8='1'
chcp 65001
```

设备名称中包含当前终端不能表示的字符时，诊断程序会使用安全替换显示；这不代表麦克风本身损坏。

## 音频断续或缓冲错误

- 关闭其他高负载音频应用。
- 确认 VB-CABLE 使用稳定的 48 kHz 格式。
- 不要同时启动多个门控实例。
- 重新启动门控后再进入实时语音。
- 若持续出现，提交 Bug 报告，并附上脱敏后的终端错误、Windows 版本、Codex 版本和音频设备名称。

不要上传录音、账号截图或包含个人路径的日志。

## 如何完全退出或卸载

只退出门控：

1. 说“结束”。
2. 退出 Codex 实时语音。
3. 在门控窗口按 `Ctrl+C`。
4. 将 Codex 麦克风恢复为“系统默认”。

移除本项目：删除克隆的项目目录即可。项目不会注册 Windows 服务或后台启动项。

卸载 VB-CABLE：使用其官方安装程序执行卸载，并按官方要求重启 Windows。卸载前确认没有其他软件依赖该驱动。
