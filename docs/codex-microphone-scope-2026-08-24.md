# Codex 麦克风选择范围核验

日期：2026-08-24

客户端版本：`OpenAI.Codex 26.818.5229.0`

## 已核验事实

- 当前客户端只有一个持久麦克风偏好字段：`microphoneInputDeviceId`。
- 客户端内置字段说明将它定义为 voice 和 dictation 共用的首选输入设备。
- 设置页内置文案也说明同一麦克风用于语音聊天和语音输入。
- 实时语音启动和普通语音输入均读取该偏好；没有发现按任务或按入口分别保存设备的字段。
- OpenAI 当前公开 Codex 文档没有说明桌面客户端支持按任务选择麦克风。

## 结论

当前客户端不能通过受支持设置把“实时语音”和“普通语音输入”永久分配到两个不同的
麦克风。把 Codex 麦克风设为 `CABLE Output` 时，Codex 内两个语音入口都会读取该
设备；这个设置也不是按任务隔离的。

## 安全可行的运行边界

1. Windows 默认麦克风始终保留为本机数字麦克风，其他应用不受影响。
2. 仅在准备使用 Codex 实时语音时启动本地门控，并把 Codex 的麦克风临时切换为
   `CABLE Output (VB-Audio Virtual Cable)`。
3. 实时语音结束后立即停止门控，并把 Codex 麦克风恢复为“系统默认”。
4. 在临时切换期间不要使用 Codex 普通语音输入；它也会经过同一门控。
5. 所有 Codex 任务共享这个客户端级设备偏好，不能声称只对单个任务生效。

## 尚未授权的替代方案

直接修改或注入 Codex 客户端以强行拆分两个音频入口属于不受支持的客户端改造，更新
后容易失效，也扩大了系统风险；本项目不采用该方案。

## 证据边界

本核验来自当前已安装客户端资源和本机设置存储的只读检查；没有修改 Codex 配置，
没有打开实时语音，也没有上传音频。客户端升级后需要重新核验。
