# Codex 实时语音“小欧”门控实施状态

日期：2026-08-24

## 已验证完成

- 默认关闭、“小欧”开启、“结束”关闭的本地状态机。
- sherpa-onnx 开放词表关键词检测和阶段 A 真人 `10/10` 验收。
- 控制词与识别异常音频不会被下游释放的延迟门控。
- 官方 VB-CABLE 驱动安装、有效签名核验、真正重启后的设备状态核验。
- 安装器擅自改变默认设备后完成回退；重启后默认输入仍为本机数字麦克风，默认输出
  仍为本机扬声器。
- 同一虚拟端点跨 MME、DirectSound、WASAPI 重复枚举的兼容处理。
- 本机麦克风 `16 kHz` 到 VB-CABLE WASAPI `48 kHz` 的本地重采样与真实双流桥。
- 一键启动入口、异常安全静音、退出时恢复 Codex“系统默认”的明确提醒。
- Codex 实时语音端到端真人三项验收：未唤醒无响应、唤醒后回答“七”、结束后不回答
  “八”。详见 `stage-b-human-e2e-acceptance-2026-08-24.md`。
- 验收结束后本地桥已停止，Codex 麦克风已由用户恢复为“系统默认”。

## 已接受的客户端边界

- 当前 Codex 的 `microphoneInputDeviceId` 同时用于实时语音和听写，不能永久分配两个
  不同设备，也不能按任务隔离。
- 用户已接受临时切换方案：仅在实时语音期间选择 `CABLE Output`，结束后恢复“系统
  默认”；临时选择期间不使用 Codex 听写。
- Windows 默认麦克风和其他应用始终保持原设置。

## 已否决路线

- Vosk 限定语法版真人结果为 `6/10`，存在误唤醒和误关闭。
- Vosk 全词表版连续两次为 `4/10`，正确控制词也被漏检。
- 不采用注入或修改 Codex 客户端来强行拆分两个入口；这属于不受支持的高风险改造。

## 尚未覆盖的可选稳定性验证

- 数小时连续运行。
- Windows 休眠与恢复。
- 麦克风或 VB-CABLE 设备热插拔。
- Codex 客户端升级后的重新兼容核验。

## 安全与发布边界

- Git 不跟踪虚拟环境、模型、日志或录音。
- 模型权重的再分发许可证尚未由发布方明确，因此模型仅保留在本机，不上传 GitHub。
- 程序不自动修改 Windows 默认设备或 Codex 设置；Codex 设备切换由用户显式完成。
