# Codex 实时语音“小欧”门控实施状态

- 默认关闭、“小欧”开启、“结束”关闭的本地状态机。
- sherpa-onnx 1.13.6 Windows CPU 运行时已安装在项目虚拟环境。
- 官方中英 3M KWS 模型已下载到 Git 忽略目录，并按 GitHub Release 提供的
  SHA-256 `68447f4fbc67e70eee3a93961f36e81e98f47aef73ce7e7ca00885c6cd3616a6`
  校验通过。
- 自定义关键词文件由官方 `text2token` 工具生成并逐行核对：只包含“小欧”和“结束”。
- 官方 `zh_5.wav` 样例经项目适配器检测出“周望军”和“落实”；Windows 中文合成语音
  经自定义词表分别检测出“小欧”和“结束”。
- 真实默认麦克风完成 1 秒打开、处理和安全关闭兼容检查；没有保存音频。
- Windows 验收启动器已统一为 CRLF 换行，并增加自动回归测试；实机 `cmd.exe`
  已验证能进入第一组提示，退出或完成后窗口会保留结果。
- 用户真人十组验收结果为 `10/10`、`complete=true`；“小陈”未误唤醒，“小欧”
  正确开启，“结束”正确关闭，完整周期最终回到关闭状态。详见
  `docs/stage-a-human-acceptance-2026-08-24.md`。
- 延迟音频门控核心：唤醒词、结束词和识别异常对应的缓冲音频不会被下游释放。
- VB-CABLE 播放端只读预检：只接受唯一的 `CABLE Input`，不会回退系统默认输出。
- 当前电脑实机预检返回 `missing`；检查前后默认设备索引均为输入 `1`、输出 `3`。
- 预检过程只枚举设备和检查格式，没有打开音频流、录音、安装驱动或修改系统设置。
- 十组真人验收程序已改用 sherpa-onnx：用户逐组确认后才临时开麦，只保留内存音频
  并输出事件/状态报告。

## 已否决路线与真人证据

- Vosk 限定语法版真人验收为 `6/10`：把“小陈”误判为“小欧”，并把普通讲话误判为
  “结束”。
- Vosk 全词表、仅最终结果、置信度 0.65 版连续两次为 `4/10`：误唤醒消失，但正确的
  “小欧”和“结束”也完全漏检。
- 因此不能继续让用户盲目重复十组验收或只调阈值；当前路线已替换为专用开放词表 KWS。

## 安全门槛

在用户明确批准安装驱动之前，后续代码和测试不得安装 VB-CABLE、不得修改
Windows 默认音频设备，也不得更改 Codex 的输入设备设置。

模型权重的再分发许可证仍未得到发布方明确说明，因此模型只能作为本机私有验证依赖，
不得提交 GitHub 或随程序分发。
